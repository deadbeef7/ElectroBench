# ElectroBench on the PlayStation Vita (scenes 2 and 4)

A homebrew port of **scene 2 (dusk ocean)** and **scene 4 (power lines / "lain")**
to the PS Vita, built as a single installable `ElectroBench-vita.vpk` that sits at
the branch root next to the code. Scenes 1 and 3 are not part of this port.

The scene sources are the desktop ones, compiled unchanged. Everything
platform-specific lives in `vitaport/`.

```
vitaport/
  Makefile               builds ./ElectroBench-vita.vpk (run from the branch root)
  include/GL/glew.h      GLEW stand-in  -> vitaGL exports the same gl* symbols
  include/SDL2/          SDL2 subset    (window, GL context, events, clock)
  src/vita_main.cxx      entry point: runs scene 2 and scene 4 in one process
  src/vita_sdl.cxx       SDL subset implementation over vitaGL + SceCtrl
  shaders/               generated GLSL 1.00 rewrites of the two scenes' shaders
  tools/build_deps.sh    builds vitaGL + vitaShaRK + math-neon into $VITASDK
  tools/make_vita_shaders.py   generates vitaport/shaders from shaders/
  tools/check_shaders.sh       regeneration + glslangValidator + syntax checks
  tools/make_icon.py     draws the LiveArea icon (pure-python PNG)
```

`lib/asset_path.hxx` gained one `#ifdef ELECTROBENCH_VITA` branch so the scenes
read assets from `app0:/` (the packed VPK) instead of walking the CWD.

## Requirements

* **vitaSDK** (autobuild, x86_64 Linux) at `$VITASDK` — for the toolchain, the
  `vita-*` packaging tools and the Sce* import stubs. The 2026 autobuild
  binaries need a host with **glibc ≥ 2.38** (they reference
  `GLIBC_2.36`/`GLIBC_2.38` symbols), i.e. Ubuntu 24.04 or newer.
* **On the console:** `libshacccg.suprx` extracted to `ur0:/data/` — vitaGL
  compiles the shaders at runtime through SceShaccCg, so a console without it
  will fail to build a single shader. (Same prerequisite as any vitaGL
  homebrew; see vitaGL's README for the extraction guide.)
* `glslangValidator` on the host, only for `make check`.

## Build

From the branch root:

```sh
sh vitaport/tools/build_deps.sh     # once: vitaGL + vitaShaRK + math-neon -> $VITASDK
make -f vitaport/Makefile           # -> ./ElectroBench-vita.vpk
make -f vitaport/Makefile check     # shader regeneration + validation only
```

`build_deps.sh` clones `Rinnegatamante/vitaGL`, `Rinnegatamante/vitaShaRK` and
`Rinnegatamante/math-neon` (none of them are packaged by `vdpm`: the public
`[vita]` repository only carries glm/libftpvita/vitagprof) and installs them into
`$VITASDK/arm-vita-eabi`. vitaShaRK needs one local shim: it includes
`<shacccg_ext.h>` and calls `sceShaccCgExt{Enable,Disable}Extensions()`, which
only exist in newer on-device `libshacccg.suprx` builds and are absent from
vitaSDK's `libSceShaccCg_stub.a`. The script injects a header plus no-op
definitions, which is the pre-extension code path older vitaGL releases used;
`shark_compile_shader_extended()` still drives SceShaccCg.

The desktop build is untouched: `make` at the branch root still produces
`build/ElectroBench` for Windows/macOS/Linux.

## Install and run

Copy `ElectroBench-vita.vpk` to `ux0:/` and install it with VitaShell (or any
VPK installer). **Hold L while launching to start with scene 4** instead of
scene 2.

| Input | Effect |
| --- | --- |
| hold **L** at launch | start with scene 4, then scene 2 |
| **SELECT** or **CIRCLE** | end the current scene, continue with the other one |
| **START** | quit the app |

The app exits after the second scene. `sceClibPrintf` output (which scene is
running, shader/compile diagnostics relayed from the scenes' stdout/stderr) is
visible in VitaShell's log or a debug console.

## How the port is put together

* **Window/context.** The Vita has one 960x544 panel and no window manager, so
  the SDL shim creates a single window at that size and `vglInitExtended()`
  takes over. `gWindowedMode` is defined `false` in `vita_main.cxx`, which makes
  both scenes adopt the reported size for their viewport, projection and HUD —
  they render natively instead of 1280x720 into a scaled surface.
* **Input.** The pad is edge-detected in `SDL_PollEvent()`; START becomes
  `SDL_QUIT`, SELECT/CIRCLE become the `SDLK_ESCAPE` keydown the scenes already
  treat as "leave this scene". So the scene loops run their real code paths.
* **MSAA.** Scene 4 asks for 4x MSAA, scene 2 for none; the requested samples
  select `SCE_GXM_MULTISAMPLE_4X` / `NONE` at `vglInitExtended()` time, and
  `SDL_GL_GetAttribute` reports back what was granted. (SceGxm has no 8x.)
* **Shaders.** `vitaport/shaders` holds GLSL 1.00 rewrites of the desktop
  shaders, generated by `tools/make_vita_shaders.py`. vitaGL rewrites
  `attribute`/`varying` into Cg for SceShaccCg and deletes `#version`,
  `#extension` and `precision` directives, but it does **not** understand
  `in`/`out`, `layout(location = N)`, `texture()`, `fwidth()` or `flat`. The
  generator applies exactly those rewrites (each one is a named rule with its
  rationale in the script) and `check_shaders.sh` fails if a 3.30-only token
  survives or if the committed tree drifts from the generator's output.
* **Scene switching.** The two scenes run back to back in one process and the
  vitaGL device is *not* torn down between them (`SDL_Quit`/`SDL_GL_DeleteContext`
  are no-ops for GXM): re-initialising GXM mid-run is the riskier path, at the
  cost of scene 2's GL objects staying resident while scene 4 runs.

## Deliberate differences from the desktop build

| Change | Why |
| --- | --- |
| `textureLod(cube, R, lod)` → `textureCube(cube, R)` in scene 2's sea shader | GLSL ES 1.00 has no LOD selection in fragment shaders; the reflection lookup uses mip level 0 instead of a distance-based blur |
| `flat out/in float vMat` → interpolated varying, `m == kMatX` → `abs(m - kMatX) < 0.5` | SceGxm has no flat varyings. Every triangle is built with one material, and the tolerance makes the test a nearest-id comparison, so an interpolation rounding ulp cannot fall into the wrong branch |
| `fwidth(x)` → `abs(dFdx(x)) + abs(dFdy(x))` | Same definition as desktop GLSL (vitaGL maps `dFdx`/`dFdy` to `ddx`/`ddy`); `fwidth` itself does not exist in its translator |
| int loop counters promoted with `float(...)` | GLSL 1.00 has no implicit int→float conversion (`i * 7.3`) |
| vsync always on | The Vita compositor is vblank-synced; the scenes' `SDL_GL_SetSwapInterval(0)` cannot be honoured |
| CPU/GPU clocks raised to 444/222/222 | default 333/166 would leave frames on the table |
| no CLI arguments, no `--screenshot`/PPM output | a VPK has no command line; scene selection is the L-trigger/LiveArea behaviour above |
| native 960x544 | the panel size, instead of the desktop 1280x720 |

## What was verified, and what was not

Verified here, on this branch:

* `sh vitaport/tools/check_shaders.sh` → `SHADER_CHECK_EXIT=0`: the committed
  shader tree is byte-identical to the generator's output, every shader is valid
  **GLSL ES 1.00** per `glslangValidator`, and no `in`/`out`/`layout`/`texture()`/
  `fwidth()`/`flat` declaration survives for vitaGL's translator.
* The generator asserts each vertex shader's `layout(location = N)` attributes
  are `0..N-1` ascending. vitaGL binds vertex streams to attributes in
  declaration order, so this is what makes the scenes'
  `glVertexAttribPointer(n, …)` calls line up.
* Clean `make -f vitaport/Makefile`: compiles, links against `libvitaGL.a`, and
  `vita-elf-create`/`vita-make-fself`/`vita-pack-vpk` emit a module with
  `.sceModuleInfo.rodata`, `.sceLib.stubs`, `.sceImport.rodata` and a `SCE\0`
  SELF header.
* VPK contents: `sce_sys/param.sfo` (`TITLE_ID=ELEB00002`), `sce_sys/icon0.png`,
  `eboot.bin`, and all 11 shaders at `shaders/ps14/…` and `shaders/pole/…` —
  byte-identical to `vitaport/shaders`, which is the tree
  `resolveAssetPath()` reads from `app0:/`.
* The desktop build is unaffected: clean `make` plus `scripts/smoke4.sh` (all
  four scenes render headless on llvmpipe) pass with the edited
  `lib/asset_path.hxx`.

**Not verified:** nothing was executed on a PS Vita or in an emulator — this
environment has no Vita runtime and no GPU, so the port has never rendered a
frame. That leaves these untested, in rough order of risk:

* runtime GLSL compilation by SceShaccCg on real hardware (the whole point of
  `libshacccg.suprx`), including whether the two shaders with derivative and
  cube-map use compile as rewritten;
* `vglInitExtended()` after the 444/222 clock change and 4x MSAA for scene 4;
* whether scene 4 fits in memory with scene 2's GL objects still resident;
* pad mapping / scene hand-over timing feel.

If a shader fails to compile on hardware, the app's own stderr text plus
`printf` diagnostics come out through `sceClibPrintf`, and the first thing to
try is `make -f vitaport/Makefile check` after editing
`tools/make_vita_shaders.py`'s rules.
